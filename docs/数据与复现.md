# 数据与复现

## 数据范围

本项目使用「美团业务选题—优惠券投放提效分析」中的 2023 年 1–6 月订单、领券和访问数据，作为个人分析作品集。

| 原表 | 原始行数 | 每行含义 | 主要字段 |
| --- | ---: | --- | --- |
| 订单 | 1,543,536 | 订单号与券编号的组合 | `Order_id`、`User_id`、`Shop_id`、`Coupon_id`、`Coupon_type`、`Biz_code`、`Pay_date`、`Actual_pay`、`Reduce_amount` |
| 领券 | 12,693,100 | 一张券 | `Coupon_id`、`User_id`、`Coupon_status`、`Receive_date`、`Start_date`、`End_date`、`Price_limit`、`Coupon_amt` |
| 访问 | 2,815,177 | 一名用户在一个自然日的访问记录 | `User_id`、`Visit_date` |

## 主要指标

| 指标 | 计算方法 |
| --- | --- |
| 实付成交额 | 归并到每笔订单一行后，加总 `Actual_pay` |
| 核销率 | 领券表状态为 2 的张数 ÷ 同一范围内全部领券张数 |
| 领券后 0–7 天可核验关联支付占比 | 在相同观察窗口内，能核验到关联支付的券数 ÷ 符合观察条件的领券数 |
| 可归属记录减免 | 核对用户、券和订单后，汇总可归到具体券的记录减免。平台实际承担金额需另行核实 |
| 门槛档 | 低档 0–10（含无门槛）、中档大于 10 至 30、高档大于 30，沿用原表单位 |
| 第二单 | 1–3 月未支付、4–5 月在样本内有首单的人，观察首单后 30 天。日期精度为天，首单当天有多笔订单归为同日 |

## 本地运行

准备 DuckDB 命令行工具。在项目根目录下创建 `_local/raw/`，把原始文件按以下名称放进去。

```text
06 美团业务选题-优惠券投放提效分析-数据1-order_detail.csv
06 美团业务选题-优惠券投放提效分析-数据2-user_coupon_receive.csv
06 美团业务选题-优惠券投放提效分析-数据3-user_visit_detail.csv
```

从项目根目录运行。以第 01 步为例。

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)
Get-Content -LiteralPath 'sql/01_原始数据盘点.sql' -Raw -Encoding UTF8 | duckdb -bail -csv
```

1. 执行 01–07 做盘点、关联核验和经营汇总。04 在 `_local/` 中建立 `meituan_analysis.duckdb`。
2. 执行 09–14，分析访问、领券和门槛。保留各步在 `数据清洗/` 生成的 CSV，后续脚本会读取其中的对账结果。
3. 执行 15 的「用户画像与基线分组」再执行「用户分层规则与规模」。16 先执行「各组后续活跃与支付」，再执行「分层后续表现」。随后执行 17–19。
4. 用同一个 DuckDB 会话按顺序运行 20、21。21 会用到 20 生成的临时明细。

```powershell
Get-Content -LiteralPath @(
    'sql/20_第4至7天第二单用券分析.sql',
    'sql/21_第二单候选券规则.sql'
) -Encoding UTF8 | duckdb -bail -csv
```

正式看板在 `bi/` 中。经营总览的刷新源在 `数据清洗/`，如果在另一台电脑刷新，请在 Power BI 的数据源设置中把 CSV 路径指向本地工作目录。

项目笔记、旧版分析、Power BI 制作工程和本地数据库收在 `_local/`，这部分由 Git 忽略。
